C99 引擎 · CLI · macOS 桌面应用

把散落在机器各处的 agent skill 收进一个仓库；需要哪一个，才取哪一个。

一台开发机上通常有好几个 AI agent，每个都有自己的 skills 目录，此外插件缓存、 项目内目录、第三方商店还散落着大量副本。把它们收敛成一个内容寻址的仓库， 让所有 agent 通过软链接访问同一份内容；再把「选哪个」交给检索—— 意图进去，命中一个出来，只读那一个的正文。 

$ make && install -m 755 build/skillctl /usr/local/bin/skillctl

引擎与 CLI 是纯 C99，源码层面零外部依赖。Windows / Linux 同样从源码构建； 桌面应用目前是 macOS（GPUI）。

01 — 三件事

一个引擎，三个面向

C 引擎是唯一真相源，CLI 是它的全部对外接口，桌面应用只是调用 CLI 的壳—— 不重写任何逻辑，所以两个前端永远看到同一份事实。

core统一

扫出 home 下所有 SKILL.md，按内容哈希去重后复制进 store， 各 agent 的 skills 根目录整体替换成指向 view 的软链。原目录永远 rename 进 trash，随时可回滚。

skillctl路由

find 把一句话的意图排成候选，show 按需取回那一个 SKILL.md。BM25F 正文索引 + 元数据启发式 + 可选稠密向量， RRF 融合；全部在进程内，不跑 Python。

app桌面

三栏：agent 树、技能墙、详情 Inspector。spawn CLI、解析 --json。 四套可切换的设计语言，深浅与强调色独立可调。

02 — 仓库长什么样

一个 store，N 个视图

身份 = 目录树的内容哈希，所以导入天然幂等、去重天然成立； agent 的加载器跟随软链接，于是对它们来说一切照旧。 

~/.skillctl/
├── units/<sha256 前 16 位>/   真实内容，按内容去重
├── views/<agent>/             每个 agent 一个目录，全是软链接
├── trash/<agent>-<时间>/       被替换掉的原目录，随时可回滚
├── index/                     BM25F 倒排索引 + 向量
└── catalog.jsonl              已知 skill 的索引

~/.zcode/skills  ->  ../.skillctl/views/zcode
~/.claude/skills ->  ../.skillctl/views/claude

扫描 · 只读

找出磁盘上所有技能，不跟随软链（44% 的条目是软链，展开会拖进几百 MB）。

入库 · 去重

按内容哈希复制进 store。同一份内容出现在五个地方，只存一份。

链接 · 可回滚

原目录 rename 进 trash，根目录换成软链。unlink 原样移回。

索引 · 可检索

正文进倒排索引，find 才有得可查；索引过期也能用，刷新即可。

03 — 路由

意图 → 命中 → 只读一个

把「所有 skill 的描述都塞进上下文」换成「提问 → 命中 → 只读一个」。 这台机器 766 个技能，已经越过 in-context 路由的拐点。 

$ skillctl find "build a godot UI with shaders"
godot-ui [stored] — Use when building user interfaces — Control nodes, themes…
godot-ui-designer [stored] — Design Godot UI layouts…

$ skillctl show godot-ui
…该 skill 的 SKILL.md 全文…

检索不是关键词匹配，而是一条按论文结论搭起来的流水线：

  • 正文进索引——去掉正文，Hit@1 掉 29–44pp（SkillRouter）
  • BM25F 五字段——name / description / profile / body / path
  • 确定性富化——profile 从正文抽取标题、触发语、围栏语言，不调用任何模型
  • 索引期去重——5-gram shingle Jaccard ≥ 0.8 的变体合并（+4.0pp）
  • 多路召回 + RRF——词面、元数据、稠密三路融合（ToolRet, Cormack 2009）

80 条分层查询，实测

查询集分六层：精确名 / 中文意图 / 英文自然语言 / 中英混合 / 仅正文才有的信号 / 同名消歧。

0.912Hit@1
0.940MRR@10
0.963Recall@3
0.988Recall@10
0.952nDCG@10

改造前（只按名字与描述的启发式）是 Hit@1 0.775 / MRR@10 0.792。 分水岭在「仅正文信号」那一层：查询信号只存在于 SKILL.md 正文里， 名字和描述一个词都没有——改造前是 0.000，现在是 0.833。

04 — 桌面应用

四套设计语言

共用同一份渲染代码，差别来自一组「姿态 token」：圆角、描边、内距、 标题字号、等宽、全大写、横线、投影、内阴影、页面渐变。

Studio

默认外观：半透明面板叠在毛玻璃上，克制的中性色 + 一个品牌强调色。

default

极简 Minimal

元素最少、内距 20px、近单色 + 单一强调色、一个 30px 超大标题，装饰为零。留白承担层次，而不是靠再塞内容。

minimalism ≠ flat

粗野 Brutal

浏览器默认材料：等宽全大写、蓝链接、1px 实线暴露结构、0 圆角零装饰、密度优先。粗来自不做修饰，不是另加修饰。

web brutalism ≠ neobrutalism

拟物 Skeuo

可命名的材质：纸面、桌面、石墨金属。统一自上而下的光照——凸起投阴影，凹陷用内阴影，两种材质不只是配色不同。

skeuomorphism ≠ neumorphism
